### 1.2 「真随机」这个词技术上站不住，建议改口径

程序实际用的是 `java.security.SecureRandom`（密码学安全伪随机数生成器 CSPRNG），**不是**物理真随机（非量子/热噪声直采）。它的真实卖点是：**不可预测、统计均匀、无取模偏差**。建议字幕口径统一为：

- ✅「密码学级不可预测随机（CSPRNG）」
- ✅「等概率无偏采样 · `nextInt(bound)` 拒绝采样消除取模偏差」
- ❌ 避免写「真随机」（懂行的人一眼挑）

**已核实的随机实现事实（可直接作为片中技术点）：**

| 位置 | 实现 | 证据 |
|---|---|---|
| 名字列表模式 | `private final SecureRandom random = new SecureRandom();` → `names.get(random.nextInt(names.size()))` | `NameListModeHandler.java:26,74` |
| 数字模式 | `SecureRandom`；跨度用 `long` 计算：`span <= Integer.MAX_VALUE` 走 `nextInt((int)span)+min`，否则 `floorMod(nextLong(), span)` 兜底；支持负数与单值范围 | `NumberModeHandler.java:35,95-104` |
| 座位模式 | `SecureRandom`；候选集只含合法座位（越界座位在读取时已过滤） | `SeatModeHandler.java:36,86` |
| 快照冻结 | 每次抽取开始 `canPick()` 做一次数据快照，`nextCandidate()` 返回的 Supplier 创建时冻结 → 滚动期间不被悬浮球等其它宿主改写数据源 | `NameListModeHandler.java:60-62` 等 |
| 滚停引擎 | `RollingPicker` 默认 50ms 一次换候选；主窗无限滚到手动停止，悬浮球 `maxTicks=20` 自动定格 | `RollingPicker.java:24,63-74` |

**一处口径地雷（我不改，等你决定）**：两个设置对话框内的「开始抽取/停止」**试抽**按钮用的是 `java.util.Random`（`java.util.Random`，48 位 LCG，可预测），与主路径的 `SecureRandom` 不一致。

- 证据：`NumberPicker.java:40,61,239`；`SeatPicker.java:51,74,378`
- 影响：如果片子里出现"全程密码学级随机"这种绝对化表述，而这个对话框试抽被展示，口径就不成立。
- 处理：**本片不展示对话框内的试抽按钮**（只展示主窗与悬浮球的抽取）。或者你批准后单独修这一处（各一行改成 `SecureRandom`），让口径完全统一。README §6 明令"死代码与已知坑勿顺手修"，故我不擅自动手。

## 2. 画面尺寸的现实约束（影响构图）

主窗口 `setSize(600, 500)`（`NamePickerApp.java:128`），标题「多功能随机抽取器」，结果标签为 微软雅黑 Bold 20pt。600×500 直接放进 1920×1080 画幅，只占约 1/5 面积，字会很小、不够格调。

**解决方案（拟采用）**：用 JVM 属性让 Swing 以 2 倍 UI 缩放原生渲染，得到清晰无插值的 1200×1000 物理像素窗口：

```
java -Dsun.java2d.uiScale=2 -jar RandomNamePicker.jar
```

1200×1000 居中放进 1080p：左右各余 360px（放标题/技术角标），上下余 40px（下方字幕安全区）。录到这个尺寸即为"真 2x 像素"，不是放大糊图。备用值 `uiScale=1.5`（900×750）。

### 7.3 BGM（由我方决定并原创合成）
按你的授权由我定，**不使用任何第三方音乐素材**以免版权风险：用 `video/tools/MakeBGM.java` 程序化合成一首原创极简电子氛围曲。
- 规格：**28.700s / 44100Hz / 立体声 / 16bit PCM**，实测峰值 **−6.0dBFS**、平均 **−18.3dB**（`volumedetect` 复核）
- 结构：A 小调 100BPM，Am–F–C–G 四和弦循环；Pad 铺底 + 16 分音符琶音 + 小节强拍低音 + 转场"叮"点；转场点前 0.5s 琶音自动加强以"咬"住画面切换；片尾淡出
- 非静音/非单音已用**频谱图**程序化验证（1094 色、低频段能量 68.9%、波形全程连续）
- 首次成片时长变了之后，`MakeBGM.HITS` 必须按新转场中心重算并重新生成，否则重音与剪切点错位

### 7.4 采集方法与保真度证据（重要）
录像并非"重画界面"，也不是普通截屏，而是**同 JVM 内驱动真实程序 + 离屏 2x 渲染**：

### 7.5 顺带发现的程序真实问题（按 README §6 未擅自修改，仅报告）
1. **「上次方案恢复」实际失效**：窗口初始化时方案下拉框的初始选择先触发方案改变事件、把「默认方案」写回 `config.properties`，随后 `restoreLastScheme()`（`NamePickerApp.java:88-106`）读到的已是被覆盖的值 → 只能恢复索引 0。日志证据：同一秒内 `已保存方案: 默认方案` 先于 `尝试恢复方案: [默认方案]`。
2. **对话框试抽随机源与主路径不一致**：`NumberPicker.java:40,61` 与 `SeatPicker.java:51,74` 用 `java.util.Random`（48 位 LCG、可预测），而主窗与悬浮球用 `SecureRandom`。本片因此回避该按钮。
3. **空方案提示文案误导**：方案无数据时日志为 `ALL_DATA_UNAVAILABLE`，界面却弹「**名单已损坏**，请重新导入」——空名单不等于文件损坏。
4. 附：`日志 LOG_DIR` 与 `config.properties` 均为**工作目录相对路径**，因此演示环境必须整目录复制，不能只拷 jar（本次演示环境为 `video/demo/`，与你的 `data/`、`log/` 完全隔离）。

### 7.6 验收方式（含能力限制）
本次会话模型**不支持读图**，因此无法用眼睛判断构图/字幕是否压图；所有画面均用程序化指标验收：`ImageAudit`（尺寸/颜色数/亮度/众数色/暗像素与内容包围盒/行剖面/双图差分）、`FrameAudit`（帧间差分剖面、运动与静止区间）、`DiffBox`（区域级变化包围盒与裁切）。**审美、字幕视觉重叠、音乐听感需你肉眼/耳朵把关。**
