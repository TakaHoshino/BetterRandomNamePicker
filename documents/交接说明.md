## 2. 关键设计口径（改动前必读）

- 贴图范围=“表面透出”：照片出现在各窗留白/容器区；表格按 T2 档位“单元格级浅透明白底”渲染
  （档 0 原生 / **1 浅（默认）** / 2 中，alpha 232/210），表头暂原生；
- 豁免铁律：输入框/密码窗永不透明（防点名/录入误读）；悬浮球、JOptionPane、JFileChooser/JColorChooser 不贴图；
- 遮罩做在背景图内（0–180，默认 40），不新增内容层之上的拦截层（不挡鼠标）；
- **主题独立页/预览窗自身不贴图**（类名不在 `BackdropManager.categoryOf` 映射表内）：避免“编辑主题的窗口被主题盖住”，
  预览也随之干净可判读；
- **预览与真实窗口同源**：预览画布底层就是真实 `WindowBackdrop`，表格单元格用 `BackdropManager` 内同一个 T2 渲染器，
  模拟内容按透明化白名单手工同构——预览所见即上窗效果；动态背景同样在预览里实时播放（同一帧源，不二次解码）；
- **动态背景口径（2026-10 路线 A）**：优先级 = **某类别单独指定的静态图 > 全局动态背景 > 全局静态图**；
  GIF 用帧自带时长、帧序列用 `theme.media.fps`；`循环` 开关为关时播到末帧自停；
  **全局单解码器**多窗口共享同一帧；窗口关闭/卸载即摘除重绘登记，无动态背景时定时器不运行（零 CPU）；
  背景音为**全局单通道**（避免多窗口回声），默认**静音**，取消勾选即播放，音量 0–100；
  主题关闭 / 媒体清空 / `Main.cleanupAndExit → shutdown()` 时停播并释放；
- **自由裁切口径（2026-10 重做 `CropSelectorDialog`）**：拖动过程中**实时**画选区（旧实现里 committed crop 恒非 null，
  导致拖动框从不绘制、松手才跳变——已修）；选区外压暗 + 三分辅助线；8 向手柄微调 + 框内拖动整体平移；
  实时显示裁切像素尺寸/比例/占比；右侧「应用后预览」用**真实 `WindowBackdrop`（CROP 模式 + 当前遮罩）**渲染，
  即"贴到窗口上是什么样"；**预设比例 11 档**：全框、16:9、4:3、1:1、9:16、3:2、16:10、21:9、2:1、4:5、3:4 ——
  取该比例的**最大**矩形并**保留当前选区中心**（中心已越界时贴边夹取），信息行会回显命中的预设名；
  ESC 取消、Enter 确定；
  交互规则：**整图状态下直接拖 = 重新框选**（否则"移动整幅"无意义、用户会以为拖不动）、框内拖 = 移动、**按住 Alt 拖 = 强制重新框选**；
  选区严格夹在图片内且不小于 12 源像素。取证工具：`tools/theme-smoke/CropDialogProbe.java`；
- 卸载/退出还原：`windowClosed` 自动还原；`Main.cleanupAndExit → BackdropManager.shutdown()` 全量还原。

## 3. 数据与持久化

- **两个备份的默认位置 = `log/`（要求）**：`log/config.properties.bak` 与 `log/theme.properties.bak`
  （常量：`ConfigManager.BACKUP_PATH` / `ThemeConfig.BACKUP_PATH`）。选 `log/` 的理由：`.gitignore` 已忽略 `log/`
  （含口令散列的备份不会被提交），且 `LogManager.clearLog()` **只删 `Modifylog.txt`、不删目录**，所以"清空日志"不会毁掉备份。
  旧位置（`data/config.properties.bak`、`data/themes/theme.properties.bak`）在首次运行时**自动迁移**到新位置
  （日志 `CONFIG_BACKUP_MOVE`；新位置已存在则清理旧文件，避免残留旧凭据）。首次写入备份时记一条
  `【… 备份位置: log/…bak】【CONFIG_BACKUP】`，路径也可从日志查到。
- **主题设置已拆分到独立文件（2026-10）**：`data/themes/theme.properties`（备份在 `log/theme.properties.bak`），与图库 `images/`、
  媒体 `media/` 同目录；键空间不变（`enabled`/`mask`/`tableTier`/`g.*`/`cat.<类别>.*`/`media.*`/`name.<id>`）。
  这样 `data/config.properties` 只留宿主设置（自启动、最小化到托盘、自动显示悬浮球、上次方案、悬浮球尺寸透明度、密码散列），
  实测从 79 行/59 个 theme 键降到 **19 行/0 个 theme 键**。实现见 `com.randomnamepicker.theme.ThemeConfig`
  （UTF-8 + 分区注释 + 键排序 + 写前备份 + 缺失自动恢复，与主配置同规格）。
  **一次性迁移**：旧版主配置里的 `theme.*` 首次运行自动搬入新文件并从主配置删除（日志 `CONFIG_MIGRATE`，冲突时以新文件为准）；
  `ConfigManager.getThemeProperty/setThemeProperty` 保留为 `@Deprecated` **转发**，旧代码/工具不受影响。
  拆分后"删 `config.properties`"的代价相应变小：只丢宿主设置与密码，**不再丢主题设置**（主题设置删的是它自己那个文件）。
  `ConfigManager.reload()` / `ThemeConfig.reload()` 供工具在还原文件后同步内存态（冒烟测试已用它们做到
  **运行前后 `config.properties` 与 `theme.properties` 逐字节一致**，不再把测试值写回用户设置）。
- **配置文件结构（2026-10 重做 `ConfigManager`）**：`data/config.properties` 改为 **UTF-8 + 分区注释 + 键排序**
  （中文不再被转义成 Unicode 码点，可直接手工编辑）；分区为「启动与窗口 / 悬浮球 / 安全 / 背景主题 / 其它（未识别键原样保留）」；
  **每次写入前把上一版另存为 `data/config.properties.bak`**；**主文件缺失但备份存在时自动从备份恢复**（记 `CONFIG_RESTORE` 日志），
  避免误删后丢密码与主题设置；密码散列由 `ConfigManager` 单写路径落盘（`PasswordManager` 不再自己读写文件——
  原实现存在"主文件缺失时改密码静默失效"与 ISO-8859-1/UTF-8 混用隐患）。**删掉主文件且无备份 ⇒ 回到出厂默认：
  自定义密码失效、内置默认密码重新生效**，同时丢 `autoStart/minimizeToTray/autoShowFloatingBall/lastScheme/悬浮球尺寸透明度/全部 theme.*`；
  主题图片与媒体文件仍在磁盘上，只是失去引用与别名。
- **悬浮球尺寸口径**：`getFloatingBallRadius()` **只判下界**（≥ `FLOATING_BALL_RADIUS_MIN`=8），**不设上界**（大小 ∈ (0, +∞)，
  可手工写成 300/3000）；设置窗滑块的 30–100 只是手动拖动范围，**载入时会屏蔽写回**（否则"滑块显示夹取 → 监听器保存"会把大值改小），
  超出范围时标签会注明"滑块仅作显示"。不透明度按 [0,255] 夹取（`Color` alpha 越界会抛异常）。
- **新增配置项**：`autoShowFloatingBall`（默认 false）= 打开主程序后自动显示悬浮球；设置窗「启动与关闭设置」里勾选，
  勾选时立即显示一次便于确认；启动路径在 `Main` 中：主窗 `setVisible(true)` 后调用 `NamePickerApp.showFloatingBallIfConfigured()`。
- **密码存储口径（2026-10 安全升级）**：配置里 `x7f9a2b1c4e8d3f6` 存的是**哈希而非明文**；写入统一为
  **PBKDF2-HMAC-SHA256 + 每密码随机盐 + 210,000 轮**，格式自描述 `pbkdf2-sha256$<轮数>$<盐B64>$<派生B64>`；
  验证用**恒定时间比较**；**旧的无盐单轮 SHA-256 仍可验证**，并在**首次验证成功后自动升级**（此时才持有明文）。
  实测成本对比（本机）：旧格式 ≈15.3 万次/秒 → 新格式 ≈29 次/秒（**慢约 5,270 倍**），弱密码离线爆破不再可行。
  **写入密码后会把 `config.properties.bak` 一并刷新**，避免备份残留可快速爆破的旧哈希而绕过升级。
  另：出厂默认密码写在源码里（`PasswordManager.BUILTIN_DEFAULT_PASSWORD`）——登录成功且检测到仍在用它时记 `SECURITY_WARN`，
  设置窗「安全设置」也会显示红色提示，提示用户尽快"修改密码"；升级/提醒均记 `SECURITY_UPGRADE` / `SECURITY_WARN` 日志。
  **边界（如实说明）**：本地密码锁防的是"拿到本程序但不知道密码的人"；能读你文件、或以你的身份运行代码的人仍可绕过
  （KDF 只提高离线爆破成本，不能防"直接改/删配置或改代码"）。
- 启用 `theme.enabled`（默认 false→未启用零影响）；遮罩 `theme.mask`(40)；表格档 `theme.tableTier`(1)；
- 全局/类别：`theme.g.image|mode|crop`、`theme.cat.<类别>.image|mode|crop`（未指定类别继承全局）；
- **图片别名**：`theme.name.<imageId>`（独立页“重命名”写此键；**不改磁盘文件名、不动引用**；清除用删键，
  依赖 §1 的 `ConfigManager` 清除落盘修复）；
- 裁剪框归一化 `x,y,w,h`；图库文件复制于 `data/themes/images/`（引用 id，不依赖原路径）；
  替换图片=以新 id 入库 + 全量重定向引用 + 继承别名 + 删旧文件（故图库里 id 会变，别名与引用不变）；
- **可解码格式（2026-10）**：白名单 = 常用格式 ∩ 运行环境有解码器 ∪ 运行环境注册的其它读取器后缀（惰性构建）；
  导入**先按内容整图解码校验**，解不出即拒收并记日志；后缀不在白名单但内容可解码者按内容规范后缀入库（`.jfif`→`.jpg`）；
  未知后缀文件若内容可解码也会被图库列出；损坏文件照旧列出但标 `[无法解码·跳过贴图]` 且不参与样式解析；
  **扩展格式**：① 把 ImageIO 读取器 jar 放 `lib/`（见 `lib/README.txt`）后重启；
  ② **ffmpeg 兜底**（`theme.media.ffmpeg`=auto/off，默认 auto；`theme.media.ffmpeg.path` 可显式指定可执行文件）——
  导入时对 WebP/AVIF/HEIC 等自动转 PNG（只在这一刻用 ffmpeg，运行时零依赖，临时文件即删）；图库“格式说明…”里有开关与自检信息；
  尺寸/头部判定均有缓存（键=路径\|大小\|修改时间），列表重绘不再重复整图解码；
  **可用性口径**：图库列出/排序用廉价头部嗅探 `looksDecodable`，而**样式解析必须用整图解码** `isUsableImage`
  （`imageDimension != null`，同样带缓存）——这样"仅头部完整、数据不全"的文件不会让某类别误判为"已启用有效背景"；
  实测：仅前 400 B 的 jpg/png 均判否；而**截断 ≥1 KB 的 JPEG 会被 ImageIO 容忍**（会画出残缺图，属既成行为）；
- 清理/复位：删除 `config.properties` 中以 `theme.` 开头行 + 清空 `data/themes/images/` 与 `data/themes/media/` 即恢复出厂；
- **动态背景与背景音（2026-10）**：媒体落盘 `data/themes/media/`（动图 `<uuid>.gif` / 序列 `<uuid>.zip` / 音频 `<uuid>.wav|.aiff|.au`）；

  别名复用 `theme.name.<id>`；"导入帧序列目录"会把目录内图片（自然序、≤600 帧）**打包成 zip 入库**（原目录不动）；
  删除媒体会清引用（全局动态背景/背景音指向它时置空）并删文件；`ThemeStore.resetToDefaults()` 一并清空这些键。

## 4. 构建与运行（交接人验证用）

```bat
:: 全量编译（等价 tools\build.bat 主路径；改码后必做）
<jdk22>\bin\javac -encoding UTF-8 -cp out -d out @sources.txt   :: sources=src 递归 .java 清单
<jdk22>\bin\jar cfm RandomNamePicker.jar manifest.txt -C out .

:: 运行
java -jar RandomNamePicker.jar        （工作目录=仓库根；plugins/ 与 data/、log/ 同根）

:: 主题 UI 冒烟取证（独立页/图库/预览/解码格式；离屏渲染，不抓桌面、不注入鼠标）
javac -encoding UTF-8 -cp out -d tools/theme-smoke/classes tools/theme-smoke/ThemeUiSmoke.java
java -cp "out;tools/theme-smoke/classes" ThemeUiSmoke
::   → 断言全文 theme_ui_shots/smoke_report.txt；截图 theme_ui_shots/*.png
```

## 6. 已知边界与后续建议

- **托盘菜单机制（2026 变更）**：原生 AWT 托盘菜单在 Windows 上因系统菜单字体（Segoe UI）不含中文字形而显示为方框（`MenuItem.setFont` 对其不生效，平台限制）；已改为 **Swing 中文弹出菜单**——托盘图标**单击/双击**在屏幕右下角唤出（含插件项，双击 350ms 去抖，插件加载后 EDT 整体重建 `Main.refreshTrayMenu`）。注意：**托盘右键不再弹菜单**，改为单击/双击唤出（详见《插件体系二次开发一期交付报告.md》与《插件开发文档.md》§15.7）。
- 不做热插拔：增删插件 jar、改宿主 jar 均需重启；
- JTable 表头、JOptionPane 等保持原生；整窗“皮肤级”沉浸（T3 自绘 L&F）未做，需另立项；
- 主题引擎依赖宿主窗口现行结构（与既有插件同族口径）：宿主改版若调整顶层布局，贴图可能失效但不伤宿主，还原路径不变；
- 主题独立页/预览窗**自身不贴图**（有意为之）；预览的模拟内容是**同构近似**（真实背景绘制 + 真实 T2 渲染器 + 手工同构控件），
  不含真实窗口业务数据；“恢复默认”不删除图库文件；
- 遗留进程提醒：交接清理时终止过一个 2026-09-05 13:55 启动的 javaw（若非你方程序请忽略）；现无残留进程。
